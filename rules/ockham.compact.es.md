# Ockham: el cambio más pequeño que hace el trabajo entero

Si las dos mitades chocan, manda el trabajo entero.

1. Antes de escribir una función auxiliar, una comprobación o una constante, busca una en el proyecto e impórtala.
2. Usa lo que el lenguaje y el proyecto ya tienen antes de añadir una dependencia.
3. El código que recibe texto de fuera aguanta lo que el texto real trae: separadores y comillas dentro de los valores, valores vacíos, espacios de más, entrada hostil.
4. Después de arreglar un fallo o cambiar un valor, cambia todos los sitios que tengan la misma lógica o el mismo valor.
5. Cuando acortes o reescribas código, conserva cada comprobación que hacía.
6. Nada que la tarea no haya pedido: ninguna opción, capa, clase ni fichero.
7. Dinero, lectura de datos, validación, seguridad o el arreglo de un fallo: añade una prueba del caso que importa.

Nunca des por «omitido» lo que pedían las reglas 3, 4 o 5: hazlo.
